# 判断规则（V0）

> 与 `V0-CONTRACT.md`、`SKILL.md` 配套。规则有冲突时以 V0 合同为准。

## 1. 输入分层与缺失处理

| 类别 | 变量 | 缺失时 |
|---|---|---|
| 客户组织 | 行业、规模、组织复杂度、IT/数字化阶段 | 标注"未知"，不推断替代 |
| 飞书使用 | 已启用模块、活跃度（高/中/低/未用）、用量趋势、覆盖部门 | 标注"未知"，不推断替代 |
| 客户表达 | 需求、痛点、反馈、投诉（优先记录原话） | 无则 L0 |
| 历史互动 | 上次结论、已有方案、关键人 | 无则省略 |
| 公开研究 | 行业动态、客户公开信息 | 可缺失，不作为编造依据 |

**证据分层**：客户事实（原话/事件）> 公开信息 > 推断 > 待验证假设。

## 2. 问题假设候选来源与优先级

候选来源（三个，不设硬优先级）：
1. 客户明确表达的需求/痛点——**提高"问题存在"可信度，但不自动成为最高优先级**。仍需验证：经营后果、相对优先级、Why now、决策权、行动意愿。
2. 使用数据暴露的缺口（模块未用/活跃下滑/覆盖少 + 相邻业务场景）。
3. 行业常见痛点（需验证，降级为验证动作）。

**收敛规则**：每轮只保留一个主假设；其余进候选池（只记名称、暂不推进原因、重启条件，不附行动）。

**防循环论证**：禁止"客户说有需求 → 选为主方向 → 围绕提问 → 礼貌认可 → 宣布价值成立"。客户礼貌认可 ≠ 认领价值（至少需要 L2 证据）。

## 3. 价值认领 L0–L4（枚举，不评分）

| 阶段 | 含义 | 可审计证据 |
|---|---|---|
| L0 | 我方假设 | 无客户确认 |
| L1 | 确认现象 | 客户原话引用或可核对事件 |
| L2 | 确认后果 | 客户原话说明对业务动作/经营结果的影响 |
| L3 | 认领价值 | 客户认为值得现在解决，并说明 Why now、成功标准 |
| L4 | 实际投入 | 客户提供数据、安排 Owner、投入会议/验证资源 |

规则：
- 转述（RM 转述客户）与推断**不得升级 L**；
- AI 建议层级，RM 确认后生效；
- "确实有这个问题"只算 L1；"影响了经营结果"才到 L2；"今年值得优先解决"才到 L3；"给人给数据给时间"才算 L4。

## 4. 两道门

- **门① 问题价值是否成立**：认领层级 ≥ L2（或 L1 + 强反证缺失）且存在可验证的 Why now；
- **门② 飞书（及替代）是否合适解法**：素材库 M2 接入前一律"待验证（素材库未接入）"。门②不过 ≠ 问题不真，只是不进入方案推进，行动改为继续验证问题价值。

## 5. 不编造规则（硬性）

- Before 只写客户确认过的事实；After 无证据时写"待验证价值"；
- 禁止补造：报表周期、参与人数、错误率、受影响决策、收益数字、行业趋势对该客户的 Why now；
- 高层语言 ≠ 把未知写得更宏大；是把已知的经营后果、指标、责任人、时间窗口讲清楚；
- "自动汇总"不必然带来"数据驱动决策"；"活跃回升"不等于"回报提升"；"OKR 覆盖子公司"不等于"战略一致"——这些因果必须逐级验证。

## 6. 状态迁移

| 触发 | 迁移 | 条件 |
|---|---|---|
| 新证据支持 | 保持 | 仅更新证据字段 |
| 关键前提被推翻 / 命中停止条件 / 候选明显更优 | 重判 | 重新走判断流程 |
| 仅资源/时点问题 | 暂缓 | 不丢链，标记原因 |
| 客户否认 / 证据不足且无验证路径 | 停止 | 保留已否定结论 |
| 已停止 | 复活 | 仅当新证据满足其重启条件 |
