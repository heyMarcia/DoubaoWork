# RM 销售经理 Copilot · V0 开发合同

> 冻结日期：2026-09-12 · 状态：**已冻结，进入 M1 开发**
> 本文档取代 `rm-judgment-framework.md`（过程稿保留存档）。任何超出本文档范围的改动须先修订本合同。

---

## 1. 产品定位（MVP 边界）

**命题**：Copilot 能否在不编造问题价值、不抬高客户认领状态的前提下，维护一个**可证伪的客户机会假设**，并推荐一个**最能让下一次判断前进、转向或停止的客户行动**。

**负责**
- 识别客户最值得优先验证的问题假设（唯一主假设）；
- 标注客户价值认领阶段（L0–L4，枚举，不评分）；
- 有素材时做飞书适配判断（M2 落地），无素材时标注"待验证"；
- 输出唯一主行动链 + Decision Card；
- 维护同一客户的判断连续性（保持 / 重判 / 暂缓 / 停止）。

**不负责（RM 判断）**
- 续费判断、报价、折扣、商务条款；
- 是否投入售前/产品/研发资源；
- 最终立项、承诺与商业推进。

**AI 与 RM 分工**
| 层 | 负责方 |
|---|---|
| 问题假设 | AI 推荐 |
| 价值认领层级 | AI 建议，RM 确认后生效 |
| 方案适配 | AI 建议 + RM 确认 |
| 商业判断 | RM 决定 |
| 状态写入 | RM 确认后 AI 写入 |

---

## 2. 判断链路（冻结）

```
已知信息 + 商业相关性标注（推断·置信度）
   → 问题价值假设（唯一主假设 + 依据/反证/最大未知）
   → 价值认领 L0–L4（枚举）
   → 两道门：①问题价值成立？ ②飞书（及替代）是否合适解法？
   → 唯一主行动链（问题→认领→方案→行动，出口一条）
   → 客户反馈 → 支持/否定/重新定义 → 状态迁移
```

**唯一主行动链**：出口只有一条链。证据不足时链可停在"问题假设 → 验证行动"，但不得有两条链。

---

## 3. 三条实施护栏（强制）

1. **L0–L4 是枚举字段**：不做评分模型，不做自动升级；AI 建议、RM 确认。
2. **Before/After 无证据时写"待验证价值"**：不得补造经营事实。
3. **主链可停在"问题假设 → 验证行动"**：证据不足时不强行进入方案层。

---

## 4. 价值认领阶段（L0–L4，枚举定义）

| 阶段 | 含义 | 可审计证据要求 |
|---|---|---|
| L0 | 我方假设（使用数据/公开信息/RM 推断） | 无客户确认 |
| L1 | 确认现象 | 客户原话引用或可核对事件 |
| L2 | 确认后果 | 客户原话说明对业务动作/经营结果的影响 |
| L3 | 认领价值 | 客户认为值得现在解决，并说明 Why now、成功标准 |
| L4 | 实际投入 | 客户提供数据、安排 Owner、投入会议/验证资源 |

规则：转述与推断不得升级 L；AI 建议层级，RM 确认后生效。

---

## 5. V0 完成标准

> **不编造、能收敛、能给下一步、能持续更新。**

- 不编造：无客户证据的经营事实为零；Before/After 无证据即"待验证价值"；
- 能收敛：每个输入都能落到唯一主行动链；
- 能给下一步：每次输出都有可执行的验证行动（找谁/聊什么/要什么承诺）；
- 能持续更新：反馈后状态正确迁移（保持/重判/暂缓/停止），已否定不无证据复活。

---

## 6. 测试约定（M3 离线验收）

| 案例 | 场景 | 预期 |
|---|---|---|
| A | 跨境电商，客户确认现象 | 主链停在问题假设+验证行动，不锁定方案 |
| B | 制造企业，活跃下滑+IT 更替 | L0，只做下降原因诊断 |
| C | 互联网公司，OKR 扩展询问 | 只确认方案兴趣，先验证扩展触发事件/Sponsor |
| D | 信息不足 | 不生成 Before/After，主链=信息收集行动 |
| E | 多轮迁移 | 否认→停止；新证据→重判；确认→推进 |

**双基线**：防幻觉基线（信息不足→必须保守，测过度自信率）；能力基线（信息充分→能收敛，测方向正确率）。
**盲评**：由未参与规则编写的 RM 独立评分——方向正确率 / 过度自信率 / 行动可执行性。

---

## 7. 范围外（本阶段明确不做）

- 数据库、评分体系、复杂证据引擎、更多状态字段；
- 续费判断与商务决策；
- 方案素材库（M2 落地，不阻塞 M1 骨架）；
- 真实客户互动（M3 验收为离线合成案例）。
